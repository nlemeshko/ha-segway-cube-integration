# Segway Cube for Home Assistant

[English](README.md) · Первый публичный beta-кандидат 0.4.0.

Экспериментальная локальная интеграция Cube 1000/2000 через Bluetooth Home Assistant, включая активные ESPHome Bluetooth proxy. Облако Segway и MQTT не нужны.

## Возможности и ограничения

- Автоматическое обнаружение Cube по аппаратному идентификатору 208, включая переименованные станции.
- Зашифрованные короткие BLE-сессии. Соединение освобождается между опросами.
- Датчики заряда (%), температуры (°C) и количества батарейных модулей, проверенные по дисплею реальной Cube.
- 67 уникальных документированных регистров: входная/выходная мощность, составные данные батарей, температуры, ёмкость, время, ошибки, предупреждения, параметры, версии и идентификаторы модулей.
- Опрос запускается с интервалом 30 секунд, подробный набор — небольшими порциями по 8 регистров; новый полный цикл начинается через 5 минут после завершения предыдущего. При запуске читаются только основные регистры; подробный опрос выполняется после загрузки интеграции и начинает с настроек управления. Время выполнения BLE-сессии добавляется к интервалу. Интервалы настраиваются.
- Количество батарей ограничивает опрос отсутствующих модулей. Неответивший регистр становится недоступным.
- Диагностика с исходными значениями без Bluetooth-пароля, серийных номеров и материалов авторизации.
- Переключатели AC/DC, R-Drive, UPS и звука кнопок; выбор мощности зарядки, режима вентилятора и таймеров AC/DC/станции/экрана. Параметры частоты AC показываются только при поддержке устройством.
- Кнопка полного обновления. Экспериментальное действие `segway_cube.set_setting` записывает только отдельные настройки и проверяет чтением их применение. Оно отключено по умолчанию.

**Заряд и основная температура проверены на реальной Cube:** rSocTemp=6420 соответствует 100% и 32 °C. Для количества модулей проверен ответ 0303 при трёх физических батареях. Если два байта количества расходятся, модульный состав не предполагается и опрос не ограничивается этим значением. Составные rTemp, rOutputInfo, rBattery*Info, флаги, ёмкость и время пока сохранены исходными значениями; отдельные показатели портов ещё не размечены. AC/DC и режимы управляются по подтверждённой конфигурации официального приложения.

## Установка через HACS

Откройте **HACS → Пользовательские репозитории**,
добавьте `https://github.com/nlemeshko/ha-segway-cube-integration` с типом
**Интеграция**, скачайте **Segway Cube** и перезапустите Home Assistant.
Затем выполните настройку, начиная с пункта 3 ниже.

## Ручная установка

1. Скопируйте `custom_components/segway_cube` целиком в `/config/custom_components/segway_cube` вашего Home Assistant.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Обнаружено → Segway Cube**. Можно также добавить интеграцию вручную.
4. Закройте Segway-Ninebot на телефоне, чтобы освободить BLE-соединение.
5. Оставьте Bluetooth-ключ пустым и включите **Создать ключ с подтверждением на станции**.
6. Подтвердите новую привязку. Она может заменить ключ приложения на телефоне.
7. Дождитесь экрана **Коротко нажмите кнопку питания Cube**, нажмите один раз, не удерживая, и дождитесь завершения. Терминал и резервная копия iPhone не нужны.

Если ключ уже известен, можно ввести его вместо создания нового. При перенастройке пустое поле и выключенный флажок привязки сохраняют действующий ключ. Собственная иконка проекта включена в компонент и отображается без загрузки из облака.

Начиная с 0.4.1, таймаут или повреждённый Bluetooth-ответ при авторизации считается
временным сбоем связи: интеграция продолжает опрос с сохранённым ключом. Повторная
авторизация требуется при отсутствии ключа или явном отказе станции. Если в 0.4.0
опрос уже остановился с сообщением «Истек срок аутентификации», после установки
обновления один раз перезапустите Home Assistant для загрузки исправления и
возобновления опроса.

Минимальная заявленная версия Home Assistant — 2026.10.1 с Python 3.14. Проверена именно эта версия; совместимость других версий ещё не подтверждена. Библиотеки Bluetooth и криптографии предоставляются Home Assistant. ESPHome proxy должен поддерживать активные подключения (`bluetooth_proxy.active: true`).

Bluetooth-имя читается из GATT; поле имени служит резервом. `auto` проверяет варианты Encryption2 и запоминает ответивший профиль. Привязка доступна и для станции, уже подключённой к приложению, после отдельного подтверждения. Кандидат ключа сохраняется до отправки станции в приватном файле `.storage/segway_cube.pairing`; при прерванной настройке он проверяется первым. Не удаляйте этот файл до завершения настройки; он содержит секретные ключи и исключён из диагностики.

## Дополнительный способ: Bluetooth-ключ из iPhone

Пароль Home Assistant не является ключом станции. Для устройств Segway ключ приложения обычно хранится в `com.ninebot.segway.plist` в значении `<СЕРИЙНЫЙ_НОМЕР>_decrypt`. Наличие подходящего ключа Cube нужно проверить — это кандидат, а не гарантия.

1. Сделайте **незашифрованный локальный backup** iPhone через Finder. Если отключать шифрование существующей резервной копии неудобно, можно экспортировать только plist через программу просмотра backup.
2. Для plist выберите `AppDomain-com.ninebot.segway → Library/Preferences/com.ninebot.segway.plist`.
3. Запустите локально:

```sh
python3 tools/extract_iphone_key.py /path/to/backup --serial CUBE_SERIAL
# Или:
python3 tools/extract_iphone_key.py /path/to/com.ninebot.segway.plist --serial CUBE_SERIAL
```

Чтобы не печатать ключ, добавьте `--output /path/to/cube-key.json`: новый файл создаётся с правами 0600. Скрипт читает только plist Segway; backup никуда не отправляется. Ключ проверяется интеграцией во время AUTH. Если нужного `_decrypt` нет, используйте встроенную привязку кнопкой.

## Выбор конкретного Bluetooth proxy

Откройте **Настройки → Устройства и службы → Segway Cube → Настроить**. В поле **Bluetooth proxy / адаптер (жёсткая привязка)** выберите нужный адаптер из списка.

Выбранный proxy используется для опросов, управления и повторной авторизации. При недоступности или занятых слотах интеграция ждёт именно этот proxy; переключения на другие нет. **Автоматически** возвращает штатный выбор Home Assistant. Исчезнувший из сети сохранённый proxy остаётся в списке как недоступный. Датчик Bluetooth signal показывает RSSI выбранного пути.

Привязка ограничивает выбор backend для каждого отдельного клиента, не изменяя глобальную маршрутизацию Bluetooth и подключения остальных интеграций. Для проверки в диагностике доступны выбранный и фактический источник последнего соединения. Совместимость этого механизма проверяется на Home Assistant 2026.10.1.

## Управление станцией

На странице устройства доступны обычные сущности Home Assistant:

- **Выход AC**, **Выход DC**, **R-Drive**, **UPS**, **Звук кнопок** — переключатели.
- **Мощность зарядки AC** — варианты в ваттах из приложения, начиная с 200 W. Верхний предел определяется возможностями станции: 1250 W или 1650 W. Это лимит входной мощности, фактическая зарядка зависит от состояния батареи.
- **Режим вентилятора** — активное охлаждение или тихий режим.
- **Отключение AC/DC/станции без нагрузки** — никогда, 15/30 минут, 1/2/6/12/24 часа.
- **Таймер экрана** — постоянно включён, 1/5/15/30 минут.
- **Частота AC** — 50/60 Hz, если этот параметр разрешён моделью. У протестированной станции соответствующий бит поддержки не установлен, поэтому переключатель частоты не создаётся.

Управление доступно сразу, включать экспериментальное действие не требуется. Переключатели читают актуальное состояние непосредственно перед записью, сохраняют остальные биты регистра и проверяют результат чтением. Значения из неподдерживаемых списков не отправляются. Настройки также можно использовать в стандартных автоматизациях `switch.turn_on`, `switch.turn_off` и `select.select_option`.

Маски и значения извлечены из конфигурации Cube, используемой официальным приложением Segway, server ID 1112, версия пакета 600002200. Частота, зарядный предел и таймеры дополнительно проверяются по `rFunSupBool`. Сбросы, обновление прошивки и отвязка аккаунта не входят в обычные органы управления.

## Экспериментальное управление

Включается в настройках интеграции. Пример действия:

```yaml
action: segway_cube.set_setting
data:
  entry_id: YOUR_CUBE_ENTRY_ID
  setting: rACStandbyTime
  value: 60
```

`value` — **исходное 16-битное значение устройства**. Для подтверждённых настроек используются те же проверки, что и у обычных сущностей; в примере 60 соответствует одному часу. Поддержаны лимит входной мощности AC, таймауты AC/DC/устройства/экрана и режимы подсветки. Запись сброса, обновления прошивки, частоты инвертора и составных флагов выходов исключена. Проверка применения — повторное чтение регистра, а не предположение по успешной GATT-записи.

## Проверки

```sh
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
python -m ruff check .
```

Тесты проверяют шифрование по фиксированным векторам, целостность, сборку пакетов, адреса Cube, фильтр обнаружения, защиту от перепривязки без подтверждения, повторные запросы привязки и восстановление ключа и ограничение GATT-пакетов 20 байтами. Тесты клиента требуют зависимостей Home Assistant; тесты протокола — `cryptography` и `pytest`.

## Проверка реального устройства

На Home Assistant 2026.10.1 успешно пройдены авторизация Gen2 через ESPHome proxy, первый опрос и последующий автоматический опрос. Исправлены зависание настройки на отсутствующих батарейных модулях и отмена записи при длительном первоначальном соединении. Ожидание первого соединения ограничено, при неудаче HA сохраняет запись и повторяет запуск в фоне. Физические значения остальных составных полей требуют отдельной проверки. Управление использует метаданные официального приложения и проверку применённого значения.


## Статус beta и поддержка

Проверена одна физическая Cube с тремя батареями на HA 2026.10.1. На станции
проверены изменение и восстановление лимита зарядки и звука. Переключение UPS
при отключении сети и остальных режимов под нагрузкой не испытывалось.
Новая физическая привязка прошла с Mac; полный цикл нового ключа через мастер
Home Assistant ещё требует отдельного испытания. Составные данные портов и
часть сведений батарей остаются исходными регистрами.

Жёсткая привязка использует внутренний механизм habluetooth; будущие обновления
Home Assistant могут потребовать изменения интеграции. Подробности — в
[TEST_REPORT.md](TEST_REPORT.md). Ошибки можно сообщать через
[GitHub Issues](https://github.com/nlemeshko/ha-segway-cube-integration/issues).
Не прикладывайте пароли, ключи, `.storage` или резервные копии телефона;
диагностика скрывает ключи и серийные номера, но содержит адреса адаптеров.
